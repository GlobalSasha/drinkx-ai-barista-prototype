# DrinkX Drink Motion Assets — где лежат продакшн-видео и рендеры

Интерфейс `/concept/` резолвит ассеты по `drinkId` через `public/concept/drink-assets.js`.
Файлы кладутся в папку напитка — **UI-код менять не нужно**: при следующем заказе
preload найдёт файлы, и видео/рендеры автоматически заменят процедурный fallback.

## Структура (для каждого напитка)

```
/public/assets/drinks/<slug>/
  render.webp        # статичный рендер для карточек (mode="card")
  assembly.webm      # видео сборки напитка (mode="assembly", приоритетный формат)
  assembly.mp4       # fallback-формат сборки
  preparation.webm   # видео реального приготовления (mode="preparation")
  preparation.mp4    # fallback-формат приготовления
  ready.webp         # финальный рендер (mode="ready")
  fallback.webp      # статичный fallback, если видео недоступно
  poster.webp        # постер, пока видео грузится
```

Слаги: `focus-flat`, `morning-boost`, `latte-soft`, `iced-balance`, `oat-vanilla-calm`,
`road-coffee`, `cold-energy`, `evening-decaf`, `no-sugar-creamy`, `after-lunch`.

## Требования к видео

- Прозрачный фон (alpha WebM) предпочтителен; иначе — фон `#1A1714`.
- Один ракурс, один стакан, одно освещение для всех напитков (см. CONCEPT.md §8).
- Без звука (плеер всегда `muted autoplay playsinline`).
- Длительность assembly: 4–6 с; preparation: может быть длиннее или зацикленным.

## Тайминг для молочных кофейных напитков (обязателен)

Видео и стадии UI должны отражать перекрытие эспрессо/молока:

```
0.0–1.8 с   эспрессо льётся в стакан
1.4–2.2 с   молоко начинается, пока эспрессо ещё доливается   ← ключевой момент
2.2–3.6 с   эспрессо остановилось, молоко продолжает
3.6–4.4 с   формируется микропена
4.4–5.0 с   напиток стабилизируется
```

Молоко обязано начаться ДО полного окончания струи эспрессо (эспрессо готов на
70–85%). Никаких полностью раздельных фаз и плоских изолированных слоёв.
В данных рецептов это поле `overlapNextMs` у стадии (см. `data.js`, focus_flat).

## Синхронизация

Стадии UI (`assemblyStages` в `data.js`) несут `telemetryEventStart/End` —
видео нарезается по тем же событиям. Пока реальных файлов нет, премиальный
процедурный рендер (`drink-renderer.js`) полностью закрывает все режимы.
